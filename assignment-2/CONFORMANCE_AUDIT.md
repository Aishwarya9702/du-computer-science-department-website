## 4. Methodology
Read all five files; extract unique requirement rows and test-case rows; construct reverse mappings from actual test references; inspect source and compare against SRS policy; parse HTML with BeautifulSoup (not an HTML conformance validator); execute `node --check` on the supplied JS (exit 0); inspect listener registrations, identifiers and whitespace; calculate selected CSS contrast ratios. No browser execution, network requests or W3C validation. Status assignments are AI-assisted source judgments, not automated proof.
## 5. Conformance definitions
Compliant = available source/document evidence supports the requirement at the inspected level; Partially Compliant = some evidence exists but a gap or missing preservation evidence remains; Non-Compliant = direct source contradiction; Not Verifiable = necessary runtime/repository/document evidence unavailable; Not Applicable = justified exclusion (none assigned). Formal acceptance and test statuses are separate.
